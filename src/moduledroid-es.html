ModuleDroid

Diseñé una librería modular que reúne tres tareas habituales de Android: navegar entre pantallas, guardar preferencias y recuperar el estado de una pantalla.

Tres plugins, uno detrás de otro

Puedes recorrer todos los ejemplos sin cambiar de pestaña.

NavigatorConfiguratorRestorer

Fragmentos de uso simplificados. Se omiten imports, clase Activity e inicialización del framework.

Navigator

Recibir el resultado de otra pantalla.

Sin el pluginKotlin / Android
private val editor = registerForActivityResult(
    ActivityResultContracts.StartActivityForResult()
) { result ->
    if (result.resultCode == RESULT_OK) {
        val name = result.data?.getStringExtra("name")
        if (name != null) showName(name)
    }
}

fun openEditor() {
    editor.launch(Intent(this, EditActivity::class.java))
}

Registrar el launcher, lanzar el Intent y extraer el resultado.

Con NavigatorModuleDroid
Navigate.toReturn(EditActivity::class).andThen {
    val name = Navigate.getResult<String>("name")
    if (name != null) showName(name)
}

Abrir la pantalla y definir qué hacer al volver.

El ejemplo muestra el lado que recibe el resultado; se omite la pantalla de edición en ambos casos. Navigator encapsula la mecánica de navegación y retorno en una llamada encadenada.

Configurator

Guardar y leer una preferencia.

Sin el pluginKotlin / Android
val preferences = getSharedPreferences(
    "settings", Context.MODE_PRIVATE
)
preferences.edit()
    .putBoolean("notifications", true)
    .apply()

val enabled = preferences.getBoolean(
    "notifications", false
)

Acceder al almacén y gestionar su editor.

Con ConfiguratorModuleDroid
Configurator.set("notifications", true)

val enabled = Configurator.get(
    "notifications", false
)

Leer y escribir desde una fachada tipada.

Encapsula SharedPreferences y su editor. El plugin también permite suscribirse a cambios y generar una pantalla de configuración.

Restorer

Conservar un contador al rotar la pantalla.

Sin el pluginKotlin / Android
var count = 0

override fun onCreate(state: Bundle?) {
    super.onCreate(state)
    count = state?.getInt("count") ?: 0
}

override fun onSaveInstanceState(out: Bundle) {
    out.putInt("count", count)
    super.onSaveInstanceState(out)
}

Guardar y recuperar el campo en los callbacks.

Con RestorerModuleDroid
@Restore
var count = 0

Declarar qué campo debe conservar su valor.

El plugin conecta el guardado y la restauración al ciclo de vida mediante anotaciones. Este ejemplo se limita a recreaciones como la rotación; no demuestra equivalencia con Bundle tras la muerte del proceso.

El reto

Navegación, preferencias y recreación de Activities suelen traer código auxiliar repartido por la app. El objetivo: encapsularlo y facilitar su reutilización.

Mi aportación

Diseñé e implementé el microkernel, sus fachadas y los tres plugins, con gestión del ciclo de vida y una aplicación de ejemplo para comparar el desarrollo.
